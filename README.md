# AI_Advent_Challenge_#9_Day3

Четыре способа рассуждения над одной задачей.

Одна и та же задача решается через API четырьмя способами. Способ задаётся **только
system prompt'ом** и числом вызовов модели: сам вопрос пользователя не меняется.
Приложение одноэкранное — вводите задачу, она уходит во все четыре режима сразу,
и ответы встают в четыре колонки рядом.

## Стек

Бэкенд на стандартной библиотеке Python (`http.server`), фронтенд — HTML/CSS/JS
без сборки. Ни `node`, ни `npm`, ни `docker` не нужны: на машине их нет.

Референсный проект отдавал статику через nginx и обращался к API прямо из браузера,
из-за чего ключ был виден в исходниках страницы (в его README это указано как известное
ограничение). Здесь запросы к модели идут через локальный Python-прокси, **ключ остаётся
на сервере и в браузер не попадает**.

## Режимы

| Режим | Что уходит в system prompt | Вызовов | Цвет |
| --- | --- | --- | --- |
| **Прямой ответ** | ничего о способе решения — только общие требования к формату | 1 | белый |
| **Пошагово** | требование разбить решение на пронумерованные шаги, выписывать промежуточные результаты, проверить решение и закончить строкой `Ответ:` | 1 | жёлтый |
| **Предпромпт** | вызов 1 — «ты инженер промптов, не решай задачу, составь промпт для её решения»; вызов 2 — сгенерированный текст идёт как system prompt | 2 | синий |
| **Совет экспертов** | три ролевых промпта параллельно (аналитик, инженер, критик), затем модератор сводит мнения | 4 | зелёный |

Критик в параллельной схеме не критикует чужие решения — при одновременном запуске
их ещё нет. Вместо этого он сначала перечисляет ловушки задачи, а потом решает сам,
обходя их. Расхождения между экспертами разбирает модератор на четвёртом вызове.

Промежуточные артефакты видны в интерфейсе: у «Предпромпта» раскрывается
сгенерированный промпт, у «Совета экспертов» — три отдельных мнения.

### Общие требования к формату

Ко всем четырём режимам добавляется один и тот же блок `FORMAT_SYSTEM`
(`app/modes.py`): отвечать простым Markdown, не использовать LaTeX и таблицы,
формулы писать в строку (`t = S / v = 1500 / 20 = 75 с`) и закончить ответ
строкой `Ответ: ...`.

Из-за этого «Прямой ответ» получает непустой system prompt — но в нём нет ни слова
о том, КАК решать задачу, только как оформить вывод. Блок не косметический:
без него `deepseek-v4-pro` на этом же вопросе выдавал `\( S = 1300 \, \text{м} \)`
и `\frac{1000}{3600}`, а в узкой колонке LaTeX нечитаем.

Ответ показывается не как обычный текст: Markdown разбирается в DOM-узлы
(`web/markdown.js`, без сторонних библиотек и без `innerHTML` — вывод модели никогда
не попадает в разметку), а строка `Ответ: ...` вытаскивается из текста и показывается
отдельной плашкой наверху карточки, чтобы итог четырёх режимов читался с одного взгляда.

Параметры сэмплинга одинаковы для всех режимов и намеренно не выведены в интерфейс
(`TEMPERATURE = 0.2`, `MAX_TOKENS = 32000`, см. `app/llm.py`): разница в ответах должна
идти от способа рассуждения, а не от настроек генерации.

## Модель и ключ

Модель `deepseek/deepseek-v4-pro` и endpoint взяты из провайдера `ai-public`
в `~/.config/opencode/opencode.jsonc`:

```
baseURL: https://ai-public.a101.ru/api
model:   deepseek/deepseek-v4-pro
```

Ключ читается из `~/.secrets/ai-public` (можно переопределить путь переменной
`AI_PUBLIC_KEY_FILE` или задать сам ключ в `AI_PUBLIC_API_KEY`). В коде и в репозитории
ключа нет.

## Запуск

```
run.bat
```

Откроется <http://127.0.0.1:5175>. Порт и хост меняются флагами:

```
python app/server.py --port 8080 --no-browser
```

Требуется только Python 3 (проверено на 3.13). Зависимостей нет.

## Сравнение

`deepseek-v4-pro` — рассуждающая модель: в `usage.completion_tokens_details`
приходит `reasoning_tokens`, и эти токены тарифицируются в `completion_tokens`.
Важное следствие для темы дня — **модель рассуждает пошагово сама, даже когда её
об этом не просят**.

Задача с проверяемым ответом и классической ловушкой — легко забыть длину самого поезда:

> Поезд длиной 200 метров движется с постоянной скоростью 72 км/ч и въезжает в тоннель
> длиной 1300 метров. Сколько секунд пройдёт с момента, когда локомотив въехал в тоннель,
> до момента, когда последний вагон полностью покинул тоннель?

Верный ответ — **75 с**: путь равен 1300 + 200 = 1500 м, скорость 20 м/с.
Типичная ошибка — 65 с (забыта длина поезда).

Два прогона одного и того же вопроса:

| Режим | Прогон 1 | Прогон 2 | Токены (1 / 2) | Время (1 / 2) |
| --- | --- | --- | --- | --- |
| Прямой ответ | **75** ✓ | **75** ✓ | 645 / 594 | 8.2 с / 9.0 с |
| Пошагово | **75** ✓ | **75** ✓ | 1677 / 811 | 20.9 с / 19.5 с |
| Предпромпт | **75** ✓ | **75** ✓ | 3681 / 3227 | 54.1 с / 41.8 с |
| Совет экспертов | **75** ✓ | **75** ✓ | 4925 / 5378 | 42.5 с / 42.8 с |

Все четыре режима запускаются параллельно, поэтому полный прогон занимает
~43 с, а не сумму (~113 с).

### Отличаются ли ответы

По итоговому числу — нет: все четыре режима дали 75 в обоих прогонах. Отличается то,
что видит пользователь:

- **Прямой ответ** — короткий расчёт в 3 строки (229 символов).
- **Пошагово** — блоки «Дано / Найти / Решение / Проверка», проверка подстановкой
  (685 символов).
- **Предпромпт** — решение плюс блок «Самопроверка», где модель отдельно считает
  встречную прикидку: 65 с + 10 с = 75 с.
- **Совет экспертов** — явное сопоставление трёх решений с разделами «Сходятся во всём»
  и «Расхождения» (762 символа).

### Какой способ дал наиболее точный результат

По точности все четыре одинаковы, поэтому разделять их приходится по цене:
режимы отличаются примерно в **8 раз по токенам** (594 против 5378) и в **5 раз
по времени** (8.2 с против 42.8 с) при одном и том же ответе.

Причина в том, что модель рассуждающая. Даже в «Прямом ответе», где о способе решения
не сказано ни слова, модель потратила 202 токена на внутреннее рассуждение и решила
задачу верно. Инструкция «решай пошагово» не добавляет ей рассуждения — оно и так есть, —
а лишь делает его видимым: в режиме «Пошагово» `reasoning_tokens` вырос до 962,
и то же рассуждение вышло в текст ответа.

Поэтому на `deepseek-v4-pro` эти способы стоит выбирать не ради точности, а ради того,
что нужно на выходе:

- **Прямой ответ** — когда нужен только результат. Самый дешёвый и быстрый.
- **Пошагово** — когда нужно показать ход решения человеку или проверить его.
- **Предпромпт** — окупается на расплывчатых задачах, где неочевиден сам метод решения;
  на задаче с одной формулой это просто удвоение стоимости.
- **Совет экспертов** — окупается там, где эксперты реально расходятся и модератору
  есть что разбирать. Здесь все трое пришли к 75 одинаковым путём, и четыре вызова
  ушли на подтверждение того, что один вызов выдал за 8 секунд. Показательно, что
  сам модератор это и зафиксировал: «Расхождений в ответе и в методе решения нет».

### Про `max_tokens` на рассуждающей модели

В референсном проекте описана ловушка: `max_tokens` — это общий бюджет на
`reasoning_content` и на `content`, рассуждение расходуется первым, и при малом
лимите приходит `finish_reason: "length"` с **пустым** ответом.

На эндпоинте `ai-public` это **не воспроизвелось**: при `max_tokens = 300` модель
вернула `finish_reason: stop` и полный текст на 269 символов (рассуждение при этом
заняло 135 токенов и в `content` не попало). То есть здесь `max_tokens` ограничивает
видимый ответ, а не сумму. Тем не менее `MAX_TOKENS = 32000` взят с запасом:
«Совет экспертов» на сложных задачах легко расходует несколько тысяч токенов.

Интерфейс на всякий случай не молчит о пустом ответе: в мета-строке появляется
красный бейдж `finish: length`, а вместо ответа выводится объяснение, куда делся текст.
Для «Совета экспертов» это важно — там обрезаться может один эксперт из трёх,
и без пометки это выглядело бы как случайный сбой.

## Структура

```
app/
  llm.py       клиент API: ключ из файла, один запрос, суммирование usage
  modes.py     четыре режима и их system prompt'ы
  server.py    http.server: статика + POST /api/run
web/
  index.html
  styles.css   чёрный фон, белый текст, цвет режима через --accent
  markdown.js  разбор Markdown в DOM без innerHTML
  app.js       четыре колонки, вызов /api/run
run.bat
```

## Ограничения

- Истории диалога нет: каждый вопрос — независимый прогон. Режимы сравниваются
  на одиночной задаче, для чего история и не нужна.
- Сервер слушает `127.0.0.1` и рассчитан на локальный запуск. Он не предназначен
  для публичного развёртывания: нет ни аутентификации, ни ограничения частоты
  запросов, а любой, кто получит доступ к порту, сможет расходовать ваш API-ключ.
